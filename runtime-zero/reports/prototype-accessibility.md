# Prototype accessibility and feedback review (RZ-010)

Scope: desktop prototype on the Lenovo WSLg setup; design viewport 1280x720
plus a narrow-window check at 1024x600. Portrait phone layouts and real-device
passes are explicitly deferred to the Android slice (RZ-026+); nothing here
claims them.

## Implemented in this pass

- **Placeholder sound with mute.** Seven deterministic cues generated by
  `tools/make_sfx.gd` (no downloads, re-running reproduces identical files):
  `ui_click`, `hit`, `guard`, `skill`, `telegraph`, `victory`, `defeat`.
  They are served by `RZAudioService` and mapped from domain events
  (`damage/defeated -> hit`, `guard_* -> guard`, `skill_used -> skill`,
  `boss_telegraph -> telegraph`, `victory/defeat/stalled`).
  The **Mute** checkbox sits on the title and combat screens, persists in the
  save, and silences active voices immediately. Replacing these with generated,
  reviewed audio is the RZ-023+ phase; until then they are clearly placeholders
  with provenance (the generator).
- **Reduced motion.** The combat toggle disables flashes and floating numbers,
  persists in the save, and is pinned by a test proving animations cannot change
  state (identical state hash with animations on and off).
- **Information is never color- or audio-only.** HP/energy/intent/outcomes are
  text; every cue has a log line counterpart (see `RZCombatText.event_line`).
- **Keyboard.** Every control is focusable (Start, Quit, Mute, equipment cards,
  Attack/Guard/Skill, Retry/Continue/Next/Replay/Title), with `1`/`2`/`3`
  shortcuts, Tab/Enter navigation and double-input protection.
- **Touch targets.** Action buttons and cards keep >= 48 logical-pixel heights;
  checked in the presentation suite.
- **Settings survive restarts** (save integration from RZ-009).

## Known gaps (honest list)

- Portrait/phone layout and true device checks are not validated yet (Android
  slice, RZ-026+); the narrow check above is a desktop window, not a phone.
- UI text scaling currently rides on the engine's canvas stretch; very large OS
  font scales have not been tested.
- Godot prototype UI does not expose OS screen-reader APIs; this would need a
  dedicated accessibility layer if it ever becomes a requirement.
- Headless runs end with harmless ObjectDB/resource warnings from the test
  harness; all suites exit 0.
- These cues are placeholders; loudness targets and final sound design belong to
  the audio phase.
